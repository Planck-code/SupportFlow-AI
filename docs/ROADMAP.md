# SupportFlow AI 开发路线与验收

> 状态：M1 已实现并通过本地验收；M2 及后续任务未开始。
> 更新日期：2026-11-02。
> 产品约束见 [PRD.md](PRD.md)，目录、表与 API 见 [ARCHITECTURE.md](ARCHITECTURE.md)。

## 1. 执行方式与全局约束

目标是从可独立验收的后端接口开始，依次完成 MVP、AI 辅助、后端增强。每次只执行一个小任务，完成检查、解释和验收后再进入下一项。

- 使用单体架构，不自行创建 Git 分支，不修改项目外文件。
- 按任务创建文件，不一次性生成后续模块、空目录或前端工程。
- 增加依赖前说明用途，核验兼容性并锁定版本。
- Handler 负责 HTTP，Service 负责规则与事务，Repository 负责数据访问。
- 重要业务逻辑有测试；数据库语义通过真实 MySQL 验证。
- 每项交付用中文说明文件变化、执行流程、学习点、运行方法、真实测试结果和未验证部分。
- README 随可运行能力同步更新，不把未来计划描述成现有功能。
- 每个任务优先补充可失败的验收测试，再实现最小行为，运行针对性检查及全量检查。

无需在开始前学完全部技术。文档中的后续任务是路线，不构成一次性实现全部阶段的指令。

## 2. 第一阶段：可独立运行的 MVP

执行顺序为 M1 → M2 → M3 → M4 → M5 → M6 → M7 → M8 → M9 → M10。

### M1 服务骨架

- [x] 建立 Go Module、Gin 服务入口、环境配置、基础请求 ID 与结构化日志。
- [x] 提供 `GET /healthz`，建立基础 README 和配置样例。
- [x] 测试健康响应和配置校验；日志不记录认证信息或请求正文。

**验收：**服务可以启动，健康接口返回 `200`；非法端口等配置错误明确报错。只校验本任务实际使用的配置，不提前要求 JWT、Redis 或模型密钥。此时不提供数据库就绪检查。

**学习点：**Go Module、包的职责、Gin 路由、HTTP 服务生命周期、`slog`。

### M2 数据库基础

- [ ] 增加 Compose MySQL、环境变量、连接池与连接超时。
- [ ] 建立编号 SQL 迁移和显式运行方法，使用迁移工具验证空库连接与版本管理；业务表在所属任务逐步添加。
- [ ] 增加 `GET /readyz`，同步 README 的数据库启动、迁移和检查步骤。

**验收：**干净数据库可执行迁移流程；数据库正常时 readiness 返回 `200`，连接失败时返回 `503`；存活接口不因数据库失败变为失败。不硬编码密码，不把容器启动等同于数据库就绪。

**学习点：**DSN、连接池、Compose、连接与查询超时、存活和就绪区别。

### M3 普通用户注册

- [ ] 新增 `users` 迁移、用户 Repository、注册 Service 和 DTO。
- [ ] 实现 `POST /api/v1/auth/register`，邮箱规范化、唯一约束、bcrypt 哈希。
- [ ] 测试重复邮箱、并发重复注册、空输入、非法邮箱及密码字节边界。

**验收：**有效注册返回 `201`；重复邮箱返回 `409`；不能注册客服或管理员；数据库和响应中没有明文密码，响应不含密码哈希。

**学习点：**DTO、唯一索引、ORM 错误映射、bcrypt、字节与字符区别。

### M4 登录与认证

- [ ] 实现登录、JWT 生成与验证、中间件、`GET /api/v1/users/me`。
- [ ] 请求查库加载当前用户和角色，不使用客户端传来的角色决定权限。
- [ ] 测试正确登录、错误凭据、无令牌、过期、伪造签名、错误算法及无效用户。

**验收：**正确登录可访问当前用户；错误凭据或令牌返回 `401`；JWT 密钥缺失时启动失败。说明客户端退出不等于撤销已签发令牌。

**学习点：**JWT、Gin 中间件、认证和授权、`context.Context`。

### M5 工作人员初始化

- [ ] 增加创建管理员和客服的命令，使用环境变量或隐藏输入读取密码，不把密码放入命令行参数或日志。
- [ ] 增加 `GET /api/v1/admin/agents` 分页接口。
- [ ] 测试角色限制、重复账号和管理员查询权限。

**验收：**能初始化两名客服和一名管理员用于演示；重复创建不会覆盖账号；普通用户和客服不能调用管理员列表；公开注册不能提权。

**学习点：**命令行入口复用业务能力、最小权限、敏感参数处理。

### M6 工单提交与查询

- [ ] 新增 `tickets/ticket_events` 迁移、模型、查询、创建事务与创建事件。
- [ ] 实现创建、列表、详情、队列和事件读取接口。
- [ ] 按角色限制查询，提供独立的队列摘要 DTO，测试分页与筛选。

**验收：**创建工单和事件一起成功或回滚；用户只能读取自己的记录；客服只能读取自己负责的详情；管理员可读取全部。未分配队列没有正文或用户资料，客服不能通过详情或事件接口绕过限制。

**学习点：**一对多、外键、分页、复合索引、数据权限、事务。

### M7 认领、分配与转派

- [ ] 实现 `claim` 和 `assignee` 接口，统一事务内工单行锁与事件写入。
- [ ] 测试管理员分配目标、角色权限、非法状态、同值分配和并发认领。
- [ ] 在真实 MySQL 中验证事件写入失败会回滚负责人及状态变化。

**验收：**两名客服同时认领仅一人成功；另一人收到 `409`。非管理员不能转派；只能转派处理中工单；转派后原客服的详情和事件读取被拒绝。

**学习点：**`SELECT ... FOR UPDATE`、事务连接传递、并发竞争、原子业务更新。

### M8 工单沟通

- [ ] 新增 `ticket_messages` 迁移，实现消息分页和回复接口。
- [ ] 回复在工单锁内判权、校验状态，消息和回复事件一起提交。
- [ ] 测试普通用户、当前客服、其他客服和管理员回复权限，以及转派与回复并发。

**验收：**只允许所属用户和当前负责客服在可回复状态写入；管理员只能读取；转派与回复按事务顺序判权；消息写入与事件写入一起回滚。

**学习点：**不可变消息、子资源授权、Unicode 长度、事务串行化。

### M9 处理闭环

- [ ] 实现优先级、解决、重开、关闭接口及对应事件。
- [ ] 用表驱动测试覆盖 PRD 中的状态和角色组合。
- [ ] 集成验证回复与解决、关闭的并发，以及状态更新和事件回滚。

**验收：**只有当前客服可解决，只有所属用户可重开，所属用户或管理员可关闭已解决工单；关闭是终态。重复状态动作返回 `409`；同值优先级更新不重复写事件。

**学习点：**显式状态机、业务错误、表驱动测试、事务边界。

### M10 可复现交付

- [ ] 增加 API Dockerfile 与 Compose 服务，保留显式迁移步骤。
- [ ] 整理 PowerShell 可执行的请求示例、示例账号创建步骤及端到端流程。
- [ ] README 覆盖环境准备、启动、迁移、初始化人员、测试及常见失败排查。

**验收：**从空数据库按文档完成注册、创建、认领、回复、解决、重开、再次解决、关闭，并另外演示管理员分配与转派。运行必要的权限和并发测试，不依赖前端。

**阶段门槛：**M1～M10 验收成立；基础检查和 MySQL 集成测试真实执行；未验证内容单列说明。

## 3. 第二阶段：AI 辅助与演示

仅在 MVP 验收后进入，顺序为 A1 → A2 → A3 → A4。

| 任务 | 交付内容 | 独立验收 |
| --- | --- | --- |
| A1 模型调用边界 | 一种供应商协议、环境配置、20 秒超时、假客户端 | 成功、超时、取消、上游错误和非法输出均有确定行为；不自动重试；不安装不必要的模型 SDK |
| A2 分析记录与接口 | `ai_runs` 迁移、触发与查询、结构校验、快照标识 | 分类在枚举内；摘要与建议长度合规；超时和异常记录失败；只允许当前负责客服触发；查询不绕过工单归属 |
| A3 人工使用闭环 | 输入截断、结果时间与过时标记、可复制编辑建议的 API 使用示例 | 最近消息变化后旧结果标记过时；人工确认后通过普通消息接口回复；AI 故障不影响工单；真实模型至少调用一次 |
| A4 最小 Vue 演示端 | Vue 3 + Element Plus，登录、用户工单、客服队列与详情、管理员分配、AI 结果展示 | 三角色可演示主流程；可复制编辑 AI 建议；模型失败仍可回复；浏览器不得获取模型密钥 |

全部任务初始状态均为未开始。A3 先通过请求示例演示，A4 再提供页面交互，避免后端验收依赖前端。

**阶段门槛：**模型调用不持有数据库事务；AI 不自动回复或改分类；一次真实验证与自动化假客户端测试分别报告。人工确认后发送的内容与普通客服回复采用相同权限校验。

**学习点：**HTTP 客户端、外部 API 超时、结构化输出、不可信输入、测试替身、失败隔离。

## 4. 第三阶段：后端工程增强

按 B1 → B2 → B3 → B4 推进，不顺带引入缓存、消息队列或后台任务框架。

| 任务 | 交付内容 | 独立验收 |
| --- | --- | --- |
| B1 Redis 登录限流 | 来源和账号维度限流、原子计数、过期策略、可信代理配置 | 触发阈值返回 `429`；Redis 故障时登录返回 `503`；已登录工单业务继续可用；验证并发计数和过期恢复 |
| B2 查询与基础统计 | `GET /api/v1/admin/ticket-stats` 按状态计数；样本数据、EXPLAIN、基准记录 | 统计与样本一致；有可复现实测结果；解释索引对具体查询的作用及限制 |
| B3 运行可靠性 | 优雅停机、HTTP 与查询超时检查、请求日志和敏感信息审查 | 停机时有界等待在途请求并释放资源；超时可验证；日志不包含密码、令牌和工单正文 |
| B4 CI 与求职展示 | 自动化检查、空库及升级迁移检查、架构讲解、演示脚本 | CI 真实通过；干净环境可运行；能解释授权、事务、索引和 AI 失败处理 |

全部任务初始状态均为未开始。B1 的具体限流阈值及窗口在任务开始时确定并配置化；B2 的性能目标根据样本和运行环境制定，不预先编造 QPS。

Redis 不用于工单缓存。若没有实际查询瓶颈，缓存继续推迟。

## 6. 测试计划与验收纪律

### 6.1 必须覆盖的高风险场景

| 场景 | 所属任务 | 期望 |
| --- | --- | --- |
| 重复邮箱并发注册 | M3 | 只有一个账号创建成功，唯一约束兜底 |
| 伪造角色、令牌过期或签名错误 | M3～M5 | 不提权，无效身份返回 `401` |
| 访问他人工单或其消息、事件 | M6、M8 | 不泄露数据，不可见返回 `404` |
| 两名客服同时认领 | M7 | 一人成功，一人 `409`，事件仅记录成功变化 |
| 转派与回复并发 | M8 | 按锁顺序校验负责人，不用事务外旧状态授权 |
| 回复与解决、关闭并发 | M9 | 状态与消息结果符合串行执行规则 |
| 事件写入失败 | M6～M9 | 工单变化、消息和事件整体回滚 |
| 非法状态转换 | M9 | 返回 `409`，原状态不变 |
| 分页、筛选、同时间记录 | M6、M8 | 排序确定，过滤不绕过权限 |
| AI 超时、非法枚举、截断、过时结果 | A1～A3 | 明确失败或标记，人工流程仍可工作 |
| Redis 阈值、并发、恢复和故障 | B1 | 正确返回 `429/503`，不无界重试 |

### 6.2 后续代码检查方法

在项目根目录运行：

```powershell
gofmt -l .
go test ./...
go vet ./...
```

`gofmt -l .` 无输出代表格式检查通过；开发时对修改过的 Go 文件使用 `gofmt -w`。检查命令失败时修复当前任务引入的问题，不用跳过代替通过。

数据库集成测试使用独立测试库，例如通过 `TEST_DATABASE_DSN` 配置；不得连接演示或真实用户数据库。没有配置时必须明确报告未运行，不能计作数据库验收通过。M2/M3 起在 README 固定集成测试调用方法；CI 中数据库服务缺失应使对应作业失败，而非静默跳过。锁、事务和约束验证必须使用 MySQL，不以 SQLite 或纯 mock 的结果替代。
